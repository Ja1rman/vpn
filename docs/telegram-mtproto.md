# Telegram MTProto с резервными выходами

Telegram подключается к одному адресу `212.22.70.156:8443`. Отдельная служба `vpn-mtproto.service` принимает MTProto и отправляет соединения через SOCKS `127.0.0.1:11092` существующего **VPN Auto**. Исходящий порядок берётся из `inventory/hosts.json → failover.egresses`: **ihor → breeze-reef → srv-41969**. Пока основной выход исправен, новые соединения используют его; распределения между исправными хостами нет.

Прокси действует внутри Telegram. При отказе выхода Telegram восстанавливает оборванное соединение, и новая попытка идёт через доступный резерв после обновления проверок пула. У всех выходов общий входной сервер `212.22.70.156`; для резервирования его полного отказа потребуется второй вход. При недоступности всего пула соединение отклоняется.

## Установка с ноутбука

Из папки проекта с настроенным SSH-доступом к входному серверу:

```bash
python3 scripts/vpnctl.py deploy-mtproto
```

Команда создаёт секрет при первом запуске и сохраняет его для следующих развёртываний. Используются закреплённый бинарник **mtg 2.3.0** и отдельная systemd-служба. Переменная `VPN_MTPROTO_SECRET` позволяет передать существующий секрет из защищённого окружения. В GitHub Actions подготовлен отдельный ручной компонент `mtproto`, использующий одноимённый Secret окружения `production`.

Закрытые файлы на ноутбуке:

| Файл | Содержимое |
| --- | --- |
| `.local/mtproto/access.md` | Готовая инструкция и ссылки для подключения |
| `.local/mtproto/access.json` | Адрес, порт, домен маскировки, секрет и ссылки |
| `.local/mtproto/config.toml` | Копия конфигурации установленного прокси |

Секрет имеет формат Fake TLS: `ee` + 16 случайных байт в hex + домен `yandex.ru` в hex. Это секрет доступа, а не пароль учётной записи Telegram. Не публикуйте ссылки и содержимое этих файлов: они дают доступ к прокси. Каталог `.local/` исключён из Git, закрытые файлы должны иметь права `600`. Не удаляйте `access.json` ради повторной установки: смена секрета потребует обновить настройки всех клиентов. В репозиторий добавляются только код и документация; секрет для автоматизации передаётся через защищённые переменные окружения/Secrets.

## Подключение Telegram

Откройте ссылку из `.local/mtproto/access.md` на устройстве с Telegram и включите прокси. Либо в настройках Telegram выберите **Данные и память → Прокси → Добавить прокси → MTProto** и перенесите сервер, порт и секрет из закрытого файла. Названия пунктов немного отличаются между платформами. Ссылку можно передавать только тем, кому нужен доступ.

## Добавление выходного сервера

Новый резерв добавляется в **VPN Auto**, отдельный список у MTProto не нужен. Следуйте [инструкции добавления сервера с ноутбука](add-server-from-laptop.md): для уже настроенного выхода добавьте строку в конец `failover.egresses`, затем выполните:

```bash
python3 scripts/vpnctl.py update-failover-pool
```

Для чистого VPS используйте описанную там команду `add_host.py --pool auto`. Сохраните прежний порядок, чтобы не менять основной IP без необходимости. После обновления пула клиентский адрес, порт и секрет Telegram остаются прежними; переустанавливать MTProto не требуется.

## Проверка службы

20 ноября 2026 года публичный MTProto-вход проверен с ноутбука для DC2, DC4 и медиа-DC2: FakeTLS и ответ Telegram `resPQ` с совпавшим nonce прошли. В изолированной копии после отключения основного выхода обмен прошёл через NL `144.31.34.165`. При отключении всех трёх выходов копия отклонила MTProto RPC. Рабочие VPN-процессы сохранили PID.

На входном сервере:

```bash
sudo systemctl is-active vpn-mtproto.service
sudo journalctl -u vpn-mtproto.service --since '10 minutes ago'
```

Повторная проверка реального протокола выполняется скриптом `verify_mtproto.py` с закрытой конфигурацией. Скрипт `verify_mtproto_failover.py --failed 1 --expected-ip 144.31.34.165` проверяет резерв в отдельных процессах, а `--failed 3` проверяет блокировку при отказе всего пула. Скрипты загружаются с ноутбука на сервер в закрытый staging через SSH. Проверка TCP-порта добавлена в существующий Prometheus. [Конфигурация mtg 2.3.0](https://github.com/9seconds/mtg/blob/v2.3.0/example.config.toml).
